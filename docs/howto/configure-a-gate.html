Configure the quality gate

Make "approved" mean to Odin what it already means to your team.

What a gate is

Odin prescribes no build system, test framework, formatter or linter. The gate is one command your repository already trusts. Odin records the exact command, its exit code and its output as a gate artifact.

  • Exit 0 approves the checkpoint and the run proceeds to verification.
  • Non-zero returns the run to implementation, until that stage reaches its attempt limit.
  • Repeated failure ends the run blocked rather than looping forever.
[gates.quality]
command = ["ctest", "--test-dir", "build", "--output-on-failure"]
timeout_seconds = 900
The gate is the only objective signal in the workflow. Agent stages produce opinions; the gate produces a fact. Make it something you would block a merge on.

Examples

# CMake + CTest
command = ["ctest", "--test-dir", "build", "--output-on-failure"]

# a build and a test suite together, via a script you already have
command = ["bash", "scripts/check.sh"]

# Meson
command = ["meson", "test", "-C", "builddir"]

# a container entrypoint, so the gate matches CI exactly
command = ["docker", "run", "--rm", "-v", ".:/src", "myproject/ci:latest"]

# Windows
command = ["cmd", "/c", "build.bat && test.bat"]

The command runs with the project root as its working directory, so relative paths behave as they would in your shell.

Environment

Children receive a small operational environment rather than everything exported by the shell that launched Odin. PATH, home and temp, locale, certificate paths and required Windows process variables are retained. Anything else is named explicitly:

[gates.quality]
command = ["bash", "scripts/check.sh"]
inherit_environment = ["CC", "CXX", "SCCACHE_DIR"]
environment = { CMAKE_BUILD_TYPE = "Release" }
timeout_seconds = 900
Why not inherit everything. A gate that inherits the whole environment also inherits every provider key in it, and those values then flow into captured output and durable state. Values imported explicitly are redacted from captured output before anything is written.

Choosing a gate

DoWhy
Make it deterministicA flaky gate turns into a revision loop and then a blocked run, with no useful diagnosis.
Make it fastIt runs on every implementation attempt. A ten-minute gate makes a three-attempt run half an hour.
Make it self-containedIt must not need a human, a prompt, or an interactive login.
Set a real timeoutDefault is 300 seconds. A hung gate is killed with its whole process tree.
Include the buildTests that do not compile are not tests. Build and test in the same gate.
