Start here

Odin is a single native executable. There is no interpreter, runtime, or package to install.

cmake -S . -B build-cpp -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build-cpp
cmake --install build-cpp --prefix out/odin

The install contains bin/odin plus its definitions, schemas, workflows, agents and skills as JSON under share/odin/. Odin resolves those assets relative to the executable, independently of whichever project you point it at.

During development use build-cpp/odin.exe on Windows or build-cpp/odin on POSIX. Every example below writes odin for either.

Command reference

CommandDoesNeeds odin.toml
odin start <task>Create a run and execute it to complete or blocked.yes
odin resume <run-id>Continue an interrupted run.yes
odin status <run-id>Inspect a run without changing it. Always exits 0.yes
odin validateCheck bundled workflows, agents, skills and templates, including cross-references.no with --self-only
odin modelsList configured profiles and routing.yes
odin doctorProbe for reachable providers.no
odin authStore, list, remove and import credentials.no
odin toolsInstall an agent CLI under .odin/tools.no
odin benchmark <task>Run one task across several profiles.yes

Exit codes

CodeMeaning
0Success. For start and resume, the run reached complete.
1Nothing found. No credentials stored, no models configured, no provider reachable. A query miss, not a failure.
2Failure. Bad configuration, an invalid task, or a run that ended blocked. The message is on stderr.
