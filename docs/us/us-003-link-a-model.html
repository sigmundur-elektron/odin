US-003   Link a model without guessing its name

Maintainer · SHIPPED

The story

As a

maintainer setting Odin up on a new machine, I want to see what this machine can actually reach right now and get paste-ready configuration for it, so that I never hand-write a model id that turns out to be wrong three stages into a run.

Model identifiers are not guessable. qwen2.5-coder:32b, qwen2.5-coder-32b and Qwen2.5-Coder-32B-Instruct are all real names at different providers. Configuration written from memory fails at the worst moment: partway through a run.

How discovery works

odin doctor                 # what is reachable right now
odin doctor --deep          # also enumerate agent CLI models
odin doctor --emit-config   # paste-ready odin.toml blocks
odin doctor --json          # machine-readable, for a front-end

Acceptance criteria

  1. Discovery probes OpenAI-compatible endpoints, Ollama's native endpoint, agent CLIs, and hosted providers whose credential is present.
  2. A closed local port is rejected by a sub-second connect attempt rather than a full HTTP timeout.
  3. An endpoint that answers 401 or 403 is reported as auth-required, distinctly from unreachable.
  4. A CLI found outside PATH is reported with its absolute path and labelled as not on PATH.
  5. --emit-config writes only model ids that were observed, never invented.
  6. Emitted configuration uses built-in adapter types and names no interpreter or script.
  7. Emitted configuration is accepted by config_load without editing.
  8. doctor exits 0 when at least one provider is ready and 1 when none is; --emit-config always exits 0.
  9. Credential values never appear in any output; only names and masked forms do.

Design notes

Adding a provider is configuration, not code. Because nearly every provider speaks the same HTTP shape, two built-in adapter types cover the ecosystem. A provider Odin has never heard of works if it exposes /v1/models and /chat/completions.
Discovery is a snapshot, not a promise. It reports what answered a moment ago. A local server stopped since then will still fail at run time; capability-aware routing with automatic fallback is future work.
