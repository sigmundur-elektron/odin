US-004   Use a provider key without leaking it

Maintainer · SHIPPED

The story

As a

maintainer using a hosted model, I want to store my provider key once and never see it again, so that it cannot reach a process listing, a log file, a durable state file, or a commit.

Agents and subagents need model access at run time, so Odin stores credentials itself rather than depending on whichever vendor CLI happens to be installed. The store is project-local, inside gitignored .odin/.

Where a secret can leak, and what stops it

odin auth set openrouter        # prompts, input not echoed
odin auth set openai --stdin    # read from a pipe, for scripts
odin auth list                  # values masked
odin auth import --from-file ~/.local/share/opencode/auth.json --provider github-copilot

Acceptance criteria

  1. An interactive auth set does not echo the secret, and warns if echo could not be disabled.
  2. Adapters receive a credential name; the value never appears in any command line.
  3. auth list, doctor and every report render secrets through masking; a value of twelve characters or fewer is replaced entirely rather than partially revealed.
  4. Masking slices on character boundaries, so a non-ASCII secret never produces invalid UTF-8.
  5. Redaction covers the raw value, its JSON-escaped form, and its ASCII-escaped form, longest first.
  6. Redaction is applied to parsed adapter output including object keys, not only to raw byte streams.
  7. The store is owner-only: mode 0600 on POSIX, an explicit current-user DACL on Windows.
  8. Environment beats disk: a named key variable, then ODIN_CREDENTIAL_<NAME>, then the store — so CI injects without writing to disk.
  9. An expired imported token is refused with a message naming the fix, rather than sent and rejected by the provider.
  10. An existing version 1 credential store remains readable; the port must not lose user data.

Design notes

An honest limit. These controls stop accidental echoes. They do not sandbox a child process: arbitrary same-user code can still read a project-local credential store. Full isolation needs a credential broker or a container boundary, which is future work and not yet built.
Stricter than what it replaced. The previous implementation's Windows branch was a documented no-op that inherited the user-profile ACL. The native store sets a protected DACL that strips the inherited entry.
