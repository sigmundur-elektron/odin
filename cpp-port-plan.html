Read this first — a caveat on "the majority".

By responsibility, this plan moves the majority to C++: the workflow engine, durable state, config, definitions, adapter invocation, and the primary CLI. By raw line count it moves ~36% of non-test Python (735 of 2,022 lines).

The gap exists because the biggest single file, harness/discovery.py (365 lines), is exactly the kind of code you asked to leave alone — platform-specific path tables, HTTP probing, TCP pre-checks. If crossing 50% by line count is a hard requirement, see §10 Stretch scope. My recommendation is that it should not be.

Gap: there is no error-handling precedent.

command_queue contains no exceptions, no std::optional, no std::expected, and no error type. Failures are expressed as early returns and bool/int results, which suits a game loop where nothing can really fail.

Odin is the opposite: five exception types drive control flow across the whole call stack (OdinError, WorkflowError, AdapterError, ContractError, CredentialError), and error messages are user-facing product surface. A convention must be chosen — see §3.

03Types and error handling

types.h — mirroring command_queue/types.h

#pragma once
#include <cstdint>
#include <string>

// identifiers are strings in odin's on-disk format, not integers.
using run_id   = std::string;
using stage_id = std::string;
using agent_id = std::string;

// a run is abandoned after this many transitions even if no stage
// has individually exceeded its attempt limit. overridden by odin.toml.
constexpr int default_max_total_transitions = 40;
constexpr int default_timeout_seconds        = 300;

// what a stage does. dispatched on explicitly - no virtuals.
enum class stage_kind : std::uint8_t {
    none = 0, agent, gate, checkpoint, stage, count
};

// the three outcomes an agent may report in a handoff/v1
enum class handoff_status : std::uint8_t {
    none = 0, approved, revision, blocked, count
};

// terminal states are complete/blocked/failed; running is the only live one
enum class run_state : std::uint8_t {
    none = 0, running, complete, blocked, failed, count
};

// json carries these as strings, so every enum needs a round trip
stage_kind     stage_kind_from_string(const std::string& s);
const char*    stage_kind_to_string(stage_kind k);

Replacing Python's raw string dispatch (engine.py:169-233) with enums is the same move command_queue makes with action_id: decouple the intent from its textual representation, and let the compiler check the switch.

// types.h - option A
enum class error_kind : std::uint8_t {
    none = 0, config, workflow, adapter, contract, io, count
};

struct odin_error {
    error_kind kind = error_kind::none;
    std::string message;
};

inline bool failed(const odin_error& e) { return e.kind != error_kind::none; }
// call sites read as one-line guards, matching net_server.cpp
odin_error err;

if (failed(err)) return cli_report_error(err);
Whichever option you pick, preserve the Python error strings verbatim. They are asserted by the existing tests and are the basis of the differential parity harness in §7. error_kind maps 1:1 onto the five Python exception classes.

04Worked example

_run_gate is the smallest function that touches config, subprocess, timeouts, and error reporting — a good template for the rest.

Python — engine.py:35-65

def _run_gate(name, spec, config, context):
    command = [_expand(p, context)
               for p in spec.command]
    environment = dict(os.environ)
    environment.update(config.environment)
    try:
        completed = subprocess.run(
            command, cwd=config.root,
            env=environment,
            stdout=subprocess.PIPE,
            stderr=subprocess.STDOUT,
            text=True, encoding="utf-8",
            errors="replace",
            timeout=spec.timeout_seconds)
    except (OSError, TimeoutExpired) as exc:
        return {"status": "failed", ...}
    return {
      "status": "passed"
                if completed.returncode == 0
                else "failed",
      ...
    }

C++ — engine.cpp, house style

// a gate is any project command; nonzero exit means
// revision, NOT a harness failure.
static gate_result engine_run_gate(
    const std::string& name,
    const command_spec& spec,
    const project_config& config,
    const run_context& context) {

    process_options opts;
    opts.command = engine_expand(spec.command, context);
    opts.working_dir = config.root;
    opts.environment = config.environment;
    opts.merge_stderr = true;
    opts.timeout_seconds = spec.timeout_seconds;

    gate_result result;
    result.command = opts.command;

    odin_error err;
    const process_result proc = process_run(opts, err);
    if (failed(err)) {
        result.passed = false;
        result.summary = "gate '" + name
                       + "' could not run: " + err.message;
        return result;
    }

    result.passed = proc.exit_code == 0;
    result.exit_code = proc.exit_code;
    result.output = proc.stdout_text;
    result.summary = "gate '" + name + "' exited "
                   + std::to_string(proc.exit_code);
    return result;
}

Note the pattern: process_run distinguishes "the command could not be launched" (an odin_error) from "the command ran and failed" (a nonzero exit_code) — exactly the distinction Python makes at adapters.py:36-47, where a nonzero exit is checked explicitly rather than raised.

Two delegation mechanisms — and only two

A. Foreground forward doctor, tools, auth

C++ re-invokes the unmodified Python CLI with the original argv, inheriting stdin/stdout/stderr, and returns its exit code.

odin doctor --deep --json
      |
      v
python -m harness.cli --config odin.toml \
       doctor --deep --json

Cost: near zero. No protocol, no serialization. Terminal inheritance means getpass at cli.py:256 keeps working with no echo, and npm progress renders live.

The seam already exists: cli.py:343-349 dispatches these three before load_config, so they have no dependency on ported code.

B. Persistent sidecar contract validation only

One long-lived Python process, spawned lazily, speaking newline-delimited JSON.

--> {"id":7,"op":"validate",
     "contract":"handoff",
     "where":"stage 'review'",
     "value":{...}}
<-- {"id":7,"ok":false,
     "error":"status: 'ok' is not one of..."}

Why persistent: a one-shot spawn costs ~80 ms on Windows; at up to 240 validations per run that is ~20 s of pure process churn. In-process it is ~1 ms.

Framing safety. Serialize sidecar messages with json.dumps(obj, ensure_ascii=True, separators=(',',':')). ensure_ascii guarantees no literal newline or non-ASCII byte can appear inside a payload, so line-delimited framing is safe without escaping or length prefixes.

Sidecar lifecycle — the struct carries its own state, and sidecar_stop is called from a small RAII guard in main.cpp:

struct sidecar {
    process_handle child;
    int  next_request_id = 1;
    bool running = false;
    int  restarts = 0;   // one restart is allowed, then we fail hard
};

void sidecar_start(sidecar& s, const project_config& config, odin_error& out_error);
json  sidecar_call (sidecar& s, const json& request, odin_error& out_error);
void sidecar_stop (sidecar& s);
  • Spawn on first contract_validate, not at startup — odin status should never pay for it.
  • Reserve stdout strictly for protocol; redirect everything else to stderr in the service's first lines.
  • On EOF or a malformed reply: restart once, replay the in-flight request, then fail with the child's captured stderr.
  • Per-request wall-clock timeout (5 s is generous) so a hung sidecar cannot stall a run.

The credential boundary — a free security win

Adapters already resolve their own secrets from a credential name passed as --credential; secrets deliberately never appear in argv. credentials.py:9-12 Because auth is forwarded to Python and adapters read the store themselves, the C++ binary never reads, holds, or writes a secret value. That removes secure-memory handling, log redaction, and getpass from C++ scope entirely.

One free optimization

Agents, skills, and workflows are immutable during a run, yet engine.py:241-242 re-reads and re-validates them on every stage. Memoize in definitions.cpp keyed by identifier. Cuts sidecar traffic from ~240 calls per run to ~40, and is behavior-preserving.

09Parity traps

Defects that will not surface in unit tests but will corrupt state files or break the GUI contract. Each is cheap to handle if known in advance.

#TrapHandling
1Non-ASCII escaping. Python's json.dump defaults to ensure_ascii=True, emitting \uXXXX. C++ libraries emit raw UTF-8. Any non-ASCII character in an LLM summary silently breaks parity. io.py:27Pass ensure_ascii=true explicitly. Add a CJK + emoji fixture in P1.
2Windows os.replace. Maps to MoveFileEx(MOVEFILE_REPLACE_EXISTING), which fails if a reader holds the target open — precisely what a polling GUI does. io.py:29Retry loop with backoff (5 attempts, 10 ms) in file_replace_atomic. Document the GUI-side FILE_SHARE_DELETE requirement.
3Trailing newline. io.py:28 writes "\n" after the JSON body.Covered by the P1 byte-diff.
4Float rendering. duration_seconds is round(x, 6) and always a float — Python writes 1.0, a naive C++ writer emits 1. Same risk for parameter_billions and OAuth expires.Store as double, never an integer variant. Add a fixture where duration lands on a whole number.
5Timeout must kill the tree. Gates run python -m unittest; tools run npm. Both spawn grandchildren that survive killing the direct child.Windows job objects; POSIX process groups. reproc++ supports both.
6Invalid UTF-8 from children. Every subprocess call uses errors="replace". Child output goes straight into a state file, so a raw invalid byte produces an unparseable artifact.Substitute U+FFFD at the decode boundary in process_run, before the value enters the DOM.
7_expand uses real str.format. A stray { in a configured gate command currently raises. engine.py:25-32Use plain substring replacement for the 4 placeholders, matching what cli_agent.py:133 already does. A deliberate, more lenient behavior change — note it in the changelog.
8Mixed time zones. Event timestamps are UTC, but run IDs and benchmark stamps use local time. engine.py:75, cli.py:378Reproduce exactly, or fix deliberately and migrate. Do not fix by accident.
9Key sort order. Python sorts by code point; std::map<std::string> sorts by UTF-8 byte. They agree for all valid UTF-8, and artifacts is an open object with agent-supplied keys.Safe as analyzed, but worth a fixture.
10run_dir is stored relative to root while task_file is absolute; relative_to throws if state_dir is outside root. engine.py:79-80Preserve both behaviors, including the throw.

11Decisions needed before P0

  1. Error handling: option A, B, or C? (§3) This is the only convention with no precedent in command_queue, and the hardest to change later. Recommend A — out_error, consistent with your out_actions idiom.
  2. Is a dependency-free single binary a goal? If yes, this plan is wrong and the estimate roughly doubles — you would need a 2020-12 schema validator, a TLS client, and native adapters. If no, proceed.
  3. Which Python does C++ invoke? Bare python on PATH is currently assumed in odin.toml:37-39 and hardcoded at tools.py:80 (note gate.py correctly uses sys.executable). Recommend resolving once at startup, with an ODIN_PYTHON override.
